## 一、上下文数据结构

每轮请求中，最后一条用户消息的末尾附带一个 `<Context>…</Context>` 块，其内容为一个 JSON 对象，含三个字段：`children`（文档结构）、`selection`（当前选区）、`discussions`（评论讨论串）。

### 1.1 `children` —— 文档结构

文档树的根是一个有序的顶层块节点数组，各块经 `children` 层层嵌套。节点分两类：

- **元素节点**：形如 `{ id, type, children, … }`。`id` 是块的唯一标识，即工具参数 `blockId` 的取值来源；`type` 决定块的种类（见下表）；容器类块经 `children` 持有子块，叶子块经 `children` 持有行内元素与文本节点。
- **文本节点**：形如 `{ text, …标记 }`。`text` 是纯文本内容，其余属性均为样式标记，不属于文本本身。一个块的纯文本 = 该块内全部文本节点的 `text` 按顺序拼接。

块类型一览：

| type                           | 说明                                               |
| ------------------------------ | -------------------------------------------------- |
| `p`                            | 段落                                               |
| `h1`–`h6`                      | 标题，级别数字越小级别越高                         |
| `blockquote`                   | 引用块                                             |
| `hr`                           | 水平分隔线（无文本）                               |
| `ul` / `ol` → `li`             | 无序 / 有序列表，`li` 内可再嵌套列表与段落         |
| `code_block`                   | 代码块                                             |
| `table` → `tr` → `td`/`th`     | 表格 → 行 → 单元格                                 |
| `toc`                          | 目录块                                             |
| `block_equation`               | 块级公式（无文本）                                 |
| `image`/`audio`/`video`/`file` | 媒体块（无文本）                                   |
| `a`、`inline_equation`         | 行内元素：链接、行内公式，与文本节点混排在叶子块内 |

文本节点常见标记：`bold`（加粗）、`italic`（斜体）、`underline`（下划线）、`code`（行内代码）、`strikethrough`（删除线）、`subscript`（下标）、`superscript`（上标）、`highlight`（高亮）、`font*`（字体相关），以及评论、修订建议等协同标记。

**注意**：行内格式是文本节点的属性，不是文本中的字符。因此用于定位的 `content` 必须是纯文本，绝不能包含 Markdown 语法。

### 1.2 `selection` —— 当前选区

形态为 `{ anchor, focus }`，或为 `null`（无选区信息）。`anchor` 与 `focus` 是选区的两个端点，先后顺序不定（`anchor` 可能位于 `focus` 之后）；两个端点相同表示选区已折叠，即为光标。

每个端点形如 `{ path, offset }`：

- `path` 是自文档树根逐层下行的下标数组：`path[0]` 是顶层块在 `children` 中的下标，`path[1]` 是该块 `children` 的下标，依此类推。端点的 `path` 总是解析到某个**文本节点**，绝不会指向块本身。
- `offset` 是在所解析文本节点的 `text` 字符串内的字符偏移，**不是**从块首起算的偏移。定位方法：按顺序拼接该块内截至（含）所解析文本节点的全部文本，再向内数 `offset` 个字符。`path` 的每一层都必须使用，漏掉任何一层都会使定位产生错位。

选区覆盖的顶层块 = 两端点 `path[0]` 所指块之间的所有块（含端点块）。

### 1.3 `discussions` —— 评论讨论串

数组，每个元素的字段如下：

| 字段                                   | 说明                                                                                                              |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `id`                                   | 讨论串标识                                                                                                        |
| `documentContent`                      | 被评注的原文（纯文本）                                                                                            |
| `isResolved`                           | 讨论串是否已解决                                                                                                  |
| `comments`                             | 回复数组，每条含 `id`、`contentRich`（富文本节点数组，阅读时取其纯文本）、`createdAt`、`userId`、`createdByAI` 等 |
| `createdAt` / `userId` / `createdByAI` | 创建时间 / 创建者 / 是否由 AI 创建                                                                                |
